# Telegram-бот студії індивідуальної друкованої продукції

Telegram-бот для супроводу клієнта під час замовлення друкованої продукції (журнали, календарі) — від вибору продукту до формування звіту для дизайнера.

## Запуск

1. Встановити залежності:
   ```
   pip install -r requirements.txt
   ```

2. Створити бота через [@BotFather](https://t.me/BotFather) та отримати токен.

3. Створити файл `.env` за зразком `.env.example`:
   ```
   BOT_TOKEN=ваш_токен_тут
   ADMIN_ID=ваш_telegram_id
   ```
   (щоб дізнатись свій ID, напишіть [@userinfobot](https://t.me/userinfobot))

4. Запустити бота:
   ```
   python bot.py
   ```

## Команди

- `/start` — почати роботу з ботом (умови співпраці, реєстрація, головне меню)
- `/cancel` — скасувати поточне замовлення на будь-якому кроці

## Функціональність

**Реєстрація** — ім'я, телефон, Telegram ID, згода з умовами співпраці.

**Журнал** — вибір підкатегорії, кількості сторінок, статей (мультивибір), послідовний прийом фото (передня обкладинка → задня обкладинка → сторінки) та матеріалів для обраних статей (текст, фото або документ).

**Календар** — вибір типу, дизайну, періоду, прийом фото (спрощений сценарій, без прив'язки фото до конкретних місяців).

**Перевірка комплектності** — після збору матеріалів бот показує список критично відсутнього (блокує підтвердження) та рекомендованого до додавання (можна пропустити).

**Навігація** — кнопка «🔙 Назад» на кроках вибору, кнопка «❌ Скасувати замовлення» та команда `/cancel` на будь-якому етапі, кнопка «✏️ Змінити дані» (перезапускає сценарій обраного продукту заново).

**Питання адміністратору** — кнопка «💬 Запитати адміністратора» перемикає бота в режим очікування тексту питання, зберігає його в базі (`ClientQuestion`) і надсилає `ADMIN_ID`, після чого клієнт повертається в попередній крок сценарію.

**Підтвердження замовлення** — після натискання «✅ Підтвердити замовлення» адміністратор отримує текстовий звіт (дані клієнта, параметри замовлення), усі фотографії та документи з підписами за призначенням, а також окремими повідомленнями — текстові матеріали статей, надіслані без файлу.

## Структура проєкту

```text
print_studio_bot/
├── bot.py
├── catalog.py
├── config.py
├── database/
│   └── models.py          # Client, Order, OrderFile, ClientQuestion
├── handlers/
│   ├── start.py            # /start, умови співпраці, реєстрація
│   ├── menu.py              # головне меню вибору продукту
│   ├── journal.py           # FSM журналу
│   ├── calendar.py          # FSM календаря
│   ├── confirmation.py      # confirm_order, cancel_order, edit_order
│   ├── admin_question.py    # питання адміністратору
│   └── cancel.py            # команда /cancel
├── keyboards/
├── states/
└── utils/
    ├── order_data.py        # робота з answers_json
    ├── validators.py        # перевірка комплектності
    └── report.py             # формування звіту адміністратору
```

## Технології

- Python 3.11+
- aiogram 3.x
- Peewee (SQLite)
- python-dotenv

## Поточні обмеження

- FSM-стан зберігається в `MemoryStorage` (оперативна пам'ять) і **не зберігається після перезапуску бота** — незавершені замовлення клієнтів втрачаються, хоча вже записані в БД дані (ім'я, телефон, обрані параметри) залишаються.
- Сценарій календаря спрощений: фотографії не прив'язуються до конкретних місяців.
- NLP та зовнішня AI-модель не використовуються — вся логіка rule-based.
- Автоматизовані unit-тести є для критичних сценаріїв (див. нижче), але повний е2е-цикл перевіряється вручну.
